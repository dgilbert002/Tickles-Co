# PHASE X.6 — Config Tab — Handoff

**Date:** 2026-05-04
**Branch:** `feature/intelligence-unified-plan`
**Commit:** `f7b7498 [phase-X.6] config tab`

## What shipped

A read-only Config tab in the Intelligence Dashboard that surfaces:

1. **Shared** — every row in `tickles_shared.public.system_config`,
   bucketed by `namespace`, sorted by `config_key`.
2. **Per-company** — each active company's `public.company_config`
   rows, sorted by `config_key`. Frozen `jarvais` excluded by
   `list_active_companies()`.

`is_secret = true` rows have their values redacted to `"***"` at the
provider boundary; the raw value never crosses into the HTTP handler.

## Files

- `shared/dashboard/config_provider.py` — 250ms-budgeted
  `ConfigSnapshotProvider`. Re-raises company-level failures so the
  outer `gather(..., return_exceptions=True)` can drop the broken
  company from the snapshot.
- `shared/dashboard/config_routes.py` — single `GET /api/config/snapshot`.
  Parses `?company=`; passes through to provider; coerces datetimes
  and Decimals via `_jsonify`. Dual-mounted via `attach_routes(app, prefix=...)`.
- `shared/dashboard/server.py` — wires `attach_config_routes` into
  the existing dual-mount loop alongside the X.4/X.5 routes.
- `shared/dashboard/web/index.html` — adds `<a data-tab="config">`
  and the Config pane (search, shared body, per-company body).
- `shared/dashboard/static/app.js` — `renderConfig` + helpers
  (`_renderSharedConfig`, `_renderCompanyConfig`, `_renderConfigFromState`,
  `_wireConfigSearch`, `_configValueCell`, `_configFmtTimestamp`).
  Idempotent search wiring via `_configSearchWired` module flag.
- `shared/tests/test_config_provider.py` — 42 tests covering parsers,
  redaction, grouping, budget enforcement, fan-out failure semantics,
  SQL surface (incl. discord_hwm exclusion), case-insensitive filter.
- `shared/tests/test_config_routes.py` — 38 tests covering parser,
  `_jsonify`, `_provider` caching, dual-mount, happy paths, 500-on-raise,
  uppercase regression, JSON coercion through the wire.

## Carryover into PHASE R-closeout

1. **`state.companyFilter` ↔ `state.company` inconsistency** — the
   dropdown change handler writes `state.company`, but the `api()`
   helper reads `state.companyFilter`. Filter changes have no effect
   until next full reload. Single source of truth needed.
2. **Cold-start pool prewarm** — first request to any provider after
   process restart loses the 250ms budget to pool initialisation and
   returns the fallback empty payload. An `on_startup` hook that
   prewarms `get_shared_pool()` and per-company pools would eliminate
   this from all tabs at once.
3. **Snapshot refresh / SnapshotBuilder integration audit** —
   verify each provider feeds the shared snapshot bus correctly;
   look for missed cache invalidation paths.
4. **`CLAUDE.md` update** — document Phase X.0–X.6 + Y deliverables.
5. **Final pytest sweep** across all dashboard test files.

## Notes for future work

- The Config tab is **read-only by design** — Phase L is a strict
  consumer. If a write surface is ever added it MUST go through the
  same per-company DB pool, parameterised SQL, and audit trail used
  by the existing pipeline writers; do not add it to `config_routes.py`.
- Per-company `company_config` schema differs from shared
  `system_config` (no `namespace`, no `is_secret`). Don't unify them
  without a coordinated migration of every reader/writer.
- Active-company list comes from env `ACTIVE_COMPANIES=['rubicon']`
  because `tickles_shared.public.companies` table doesn't exist yet.
  Once that table lands, `list_active_companies()` will pick it up
  automatically.
