## What was built

A new top-level **News Feed** tab in the owner dashboard surfacing the
shared `public.news_items` stream with optional per-company narrowing,
source / has-media filters, and 24h / 7d / 30d windowing.

### Backend

- [`shared/dashboard/news_provider.py`](shared/dashboard/news_provider.py:1)
  — `NewsFeedProvider` class. 250ms hard budget enforced via
  `asyncio.wait_for`. Reads only `public.news_items` (no `media_items`
  join — `has_media` and `media_count` live directly on `news_items`).
  Per-company filtering goes through `_company_instruments(company)`
  which derives the symbol set from `tickles_<company>.trades` →
  `tickles_shared.instruments`. Instrument resolution runs **inside**
  the budget. Helpers split out:
  - `_validate_window`, `_validate_source`, `_normalise_limit`
  - `_resolve_company`, `_company_instruments`,
    `_read_company_instrument_ids`, `_read_symbols_for_ids`
  - `_run_with_budget` (mirrors learning-providers pattern)
  - `_build_query` (parameterised SELECT — split out so it can be
    unit-tested without touching DB pools).
- [`shared/dashboard/news_routes.py`](shared/dashboard/news_routes.py:1)
  — single endpoint `GET /api/news/feed` mounted under both `""` and
  `"/dashboard"` prefixes by `server.build_app`. Query parsers:
  `_parse_window` (24h/7d/30d), `_parse_company` (`all` → None),
  `_parse_source` (allow-list silently drops unknowns),
  `_parse_bool` (tri-state), `_parse_limit` (default 100, cap 500).
  `_jsonify` recursively coerces Decimal/datetime/date so handler
  can call `web.json_response` directly.
- [`shared/dashboard/server.py`](shared/dashboard/server.py:409)
  — added the news_routes mount block alongside learning_routes.

### Code-reviewer fixes applied
- `_query` refactored into `_query` + `_build_query` (sub-50-line)
- `_company_instruments` silent-fallback documented with `.. note::`
- JS hardcodes (`100`, `colspan="6"`) replaced with named constants

### Bug-hunter fixes applied
- **MEDIUM** — `_company_instruments` was running **outside** the
  250ms budget. Two DB roundtrips before the timer started. Fixed
  by moving the lookup inside `_do_fetch`.
- **LOW** — `renderNews` "Loading…" check used
  `!tbody.children.length` which was always false because the
  default markup ships a `<tr>` placeholder, so subsequent
  refreshes kept stale rows. Fixed: always show "Loading…".

### Bug-hunter findings deferred / won't-fix
- Company-name case sensitivity in `_resolve_company` — documented
  as intentional ("typos degrade gracefully").
- Pre-existing `_esc()` `\u0026` literal sequence — works correctly,
  not introduced by X.4.
- Tab-switch race — pre-existing across all dashboard tabs; an
  abort-controller refactor belongs in its own phase.
- News-row "View Source" link from `metadata.url` — backend doesn't
  currently expose `metadata`; defer to future enhancement.
