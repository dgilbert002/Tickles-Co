## What was built

A right-side slide-in drawer that opens from any row carrying a
`news_item_id` (Signals, Positions, Interpretations, News tabs)
and renders the full LLM + quant + ChartHacker interpretation
timeline for that news item, plus single-row open by `interp_id`.

### Backend

- [`shared/dashboard/interpretation_drawer_provider.py`](shared/dashboard/interpretation_drawer_provider.py:1) — 518-line provider
  - `fetch_by_news_item(news_item_id, limit)` — all interpretations for one news item, ordered DESC
  - `fetch_by_id(interp_id)` — single interpretation by primary key
  - `_validate_id` rejects `0`, negatives, non-numeric strings, `None`
  - `_normalise_limit` clamps to `[1, DRAWER_LIMIT_CAP]` with default
  - `_run_with_budget` wraps every public method in `asyncio.wait_for`
    at `DRAWER_PROVIDER_TIMEOUT_S` (250ms) and swallows exceptions →
    returns the documented fallback. Provider never raises into the
    request handler.
  - `_select_clause()` joins `signal_interpretations` ⟕ `news_items`
    ⟕ `media_items`, returns LLM + quant + ChartHacker columns +
    consensus + tags + thesis + media URL.
  - `_row_to_dict` handles all-null optional fields, prefers
    `instrument_exchange` over `exchange` when both present.

- [`shared/dashboard/interpretation_drawer_routes.py`](shared/dashboard/interpretation_drawer_routes.py:1) — 233-line route module
  - Single endpoint: `GET /api/interpretations/drawer`
  - Exactly-one-of `news_item_id` / `id` validation; both or neither → 400
  - `_parse_positive_int` rejects `"1.9"` strings (defense-in-depth vs
    provider's `int()` truncation, which is documented + tested)
  - `_jsonify` recursive Decimal/datetime/date/dict/list coercion
  - Response shape exposes BOTH id keys (one always null) — intentional,
    asserted in `test_drawer_news_item_id_happy_path`
  - `_provider(request)` caches the provider on `request.app['_interp_drawer']`
    — stateless + GIL-safe
  - `attach_routes(app, prefix='')` for dual-mount

- [`shared/dashboard/server.py`](shared/dashboard/server.py:419) — drawer routes mounted inside the existing
  `for prefix in ("", "/dashboard"):` loop alongside news + learning routes.

## Quality gates

### code-reviewer 3-pass

- **0 CRITICAL / 2 MEDIUM / 11 LOW**
- Both MEDIUM fixed in [`shared/dashboard/static/app.js`](shared/dashboard/static/app.js:1):
  1. **Media preview URL** — switched from `_esc(...)` HTML escaping
     to `encodeURIComponent(...)` URL escaping. HTML escape doesn't
     percent-encode `?`, `&`, `=`, etc., so a media URL with `&`
     would silently break query parsing on the static handler.
  2. **`_wireDrawerClicks` idempotency** — wired listeners were being
     re-attached on every tab refresh, causing duplicate handler
     invocations. Added module-level `_drawerWired` flag for the
     overall function and per-element `dataset.drawerWired` flag for
     each container so attaching is one-shot per element.
- 11 LOW findings deferred (cosmetic / out-of-scope, documented in skill output).

## Known pre-existing failures (NOT introduced by X.5)

- `state.companyFilter` is read in [`shared/dashboard/static/app.js`](shared/dashboard/static/app.js:26) but the dropdown
  writes `state.company` in [`shared/dashboard/static/app.js`](shared/dashboard/static/app.js:1392).
  Effect: company filter is silently ignored on all API paths.
  Affects every tab equally. Out of scope for X.5; flag for X.6 or
  R-closeout sweep.
- Auto-refresh `setInterval(refresh, 10000)` re-renders cards while
  drawer is open. `_drawerLastFocus` then references a detached node
  and focus restoration on close snaps to `<body>`. Cosmetic only.
